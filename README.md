# Мониторинг K GYM & YOGA

На этом Mac установлен локальный скрипт. Автозапуск: каждую минуту и при входе в macOS.
**Telegram подключён, вход Google сохранён. Чтение текущей загрузки подтверждено: скрипт получил 59/100, совпавшие с обычной вкладкой Google Maps.**

**Проверки работают без окон.** Скрипт запускает Chrome в безоконном режиме (`headless`) с настольным User-Agent установленной версии Chrome, читает карточку и завершает процесс. Окон и новых вкладок в вашем обычном браузере не появляется. Автоматического перехода к режиму с окном нет, даже при недоступных данных. Окно открывается только при явно запущенной настройке входа Google. На macOS используется настоящее защищённое хранилище Chrome, совместимое с ручным входом.

## Подключение

Если Telegram уже подключён, **Настроить.command** сразу открывает обычный Chrome с отдельным профилем без вопросов о токене. Вход выполняется вручную, без Playwright, отладочного порта и изменения защит браузера. Войдите в Google, проверьте наличие Live и напишите «готово» в чат. Помощник выполнит команду `finish-login`: она закроет только запущенный скриптом Chrome, проверит фоновое получение данных и восстановит автозапуск только при наличии live-данных. При ошибке, отсутствии live или закрытом зале автозапуск остаётся выключенным до успешной повторной настройки. Альтернатива — завершить именно этот экземпляр Chrome через меню Chrome → Quit. Закрытие последней вкладки на macOS может оставить процесс работающим. На время входа фоновые проверки приостановлены.

Файл `.command` нужно запустить двойным щелчком **в Finder**: ссылка на файл в чате может лишь открыть его содержимое в редакторе. Отдельная команда `login` в `monitor.mjs` также запускает только вход Google.

При первоначальной настройке без подключённого Telegram:

1. Дважды щёлкните **Настроить.command** в Finder. Откроется Terminal.
2. Создайте бота через [@BotFather](https://t.me/BotFather), команда `/newbot`. Вставьте токен в Terminal — ввод скрыт, в чат его отправлять не нужно.
3. Откройте своего бота и нажмите **Start**. Вернитесь в Terminal. ID личного чата обычно определяется автоматически; если у бота несколько пользователей, укажите свой числовой chat_id.
4. Выберите порог или оставьте 30. Скрипт отправит проверочное сообщение.
5. Откроется обычный Google Chrome с отдельным профилем. При необходимости войдите в Google самостоятельно, без синхронизации браузера. Убедитесь, что в карточке зала виден **Live / «Сейчас»**, затем напишите «готово» в чат. CAPTCHA, если появится, проходится вручную.
6. Скрипт отдельно проверит чтение в фоновом Chrome и напечатает результат. Автозапуск включается только при `status: live`; при неудаче повторите настройку в часы работы зала. Если `live: null` или `status: error`, получение загрузки ещё не работает. Наличие показателя в обычном браузере не гарантирует доступ в профиле скрипта.

Обычный профиль браузера не используется и не копируется. Вход хранится в отдельном локальном профиле. Не запускайте настройку в двух окнах одновременно. Google может блокировать вход в автоматизированном браузере: поэтому авторизация отделена от фонового чтения данных. Успешный ручной вход не гарантирует, что фоновое чтение будет доступно.

## Правила

- Автоматические уведомления, включая предупреждения о сбоях, отправляются только с **09:00 до 20:00 по времени Нячанга (UTC+7)**. Ответы на команды доступны в любое время.
- Низкая загрузка: значение Google **не выше 30 из 100** в трёх последовательных подтверждениях с интервалом не меньше 10 минут, охватывающих не менее 20 минут. Перед отправкой выполняется ещё один свежий общий запрос и сверка показателя с видимым live-графиком Google Maps. Высокое значение, несовпадение, отсутствие live или ошибка отменяют уведомление и сбрасывают серию. Запросы Google выполняются раз в 10 минут; загруженность между запросами неизвестна. Частые ручные проверки не увеличивают счётчик; ошибка, закрытие зала или повышение выше порога сбрасывают серию. Это относительный индекс посещаемости, не процент занятых тренажёров.
- Повторное уведомление разрешается после подъёма до 45 и следующего спада; минимальный интервал между уведомлениями — 1 час.
- Отсутствие live, ошибка парсинга и проблемы сети не считаются нулевой загрузкой. Нулевой показатель Google тоже считается недостоверным: в журнале были временные нули перед возвратом высокой загрузки. Он сохраняется для диагностики как `rawLive: 0`, сбрасывает подтверждения и не вызывает уведомление о низкой загрузке. Поэтому при действительно пустом зале с показателем 0 уведомления также не будет. После трёх неудачных проверок отправляется одно предупреждение о недоступности за непрерывный сбой.
- Часы по карточке Google на момент установки: пн–сб **05:30–20:00**, вс **06:00–12:00**, часовой пояс **Нячанга (UTC+7)**. За пределами этих часов Google не опрашивается. Праздничные изменения расписания автоматически не отслеживаются; если браузер явно показывает Closed, уведомления о низкой загрузке подавляются.
- Mac должен быть включён, пользователь должен войти в macOS, нужен интернет. Во сне и при выключенном компьютере проверок нет; компьютер скрипт не будит. Пропущенные интервалы не воспроизводятся; перерыв между проверками более 13 минут начинает серию заново.
- Push на телефон зависит от включённых уведомлений Telegram и режима «Не беспокоить».

## Управление

В личном чате с Telegram-ботом:

- `/start` — подписаться на уведомления. Подписаться может любой пользователь по ссылке бота. Бот отвечает подтверждением; повторный `/start` также снимает личную паузу. Ответ обычно приходит в течение минуты, пока Mac владельца работает и имеет интернет.
- У каждого подписчика своя пауза, подтверждения низкой загрузки и интервал повторных уведомлений. Проверка Google общая; если все получатели на паузе, Google не опрашивается. Ошибка доставки одному получателю не мешает остальным.

- `stop` или `/stop` — выключить свои автоматические уведомления до 00:00 по времени Нячанга, включая предупреждения о сбоях. В сообщениях бота есть кнопка «🏋️ Уже сходил — выключить на сегодня» с тем же действием.
- `/resume` — вернуть уведомления сегодня. Обычные пороги, подтверждения и интервалы продолжают действовать.
- Команды читаются при минутных проверках, в том числе вне часов работы и во время паузы. Mac должен работать и иметь интернет; после сна возможна задержка. Команда `stop` из предыдущего дня не отключает уведомления на новый день; нажатие кнопки в старом сообщении отключает их на сегодняшний день.
- После полуночи уведомления включаются автоматически; пауза сохраняется при перезагрузке. Если все подписчики на паузе, Google не опрашивается. После неё нужны новые подтверждения низкой загрузки.
- При недоступности чтения команд обычные уведомления мониторинга временно не отправляются, чтобы не пропустить команду остановки. Независимый контроль учитывает личную сохранённую паузу каждого подписчика.

- **Статус.command** — включён ли автозапуск, последняя проверка, настроен ли Telegram.
- **Проверить.command** — разовая проверка с обычными правилами уведомлений; вне рабочих часов опроса нет.
- **Остановить.command** — остановить мониторинг сейчас. Для запуска снова используйте настройку. Задание остаётся установленным и запускается после нового входа в macOS.
- **Удалить автозапуск.command** — удалить задание автозапуска, сохранив настройки и отдельный профиль Chrome.

Рабочая папка: `~/Library/Application Support/GymMonitor/`.

- `config.json` — пороги, расписание, токен и ID чата. Файл доступен только вашему пользователю (`600`). Не отправляйте его другим.
- `heartbeat.json` — время последней полностью завершённой проверки, включая проверки вне часов работы.
- `fatal.json`, `history.jsonl`, `launchd-errors.log` — диагностика аварийных сбоев; сырые сообщения парсера конфигурации не записываются.
- `watchdog.rb` — независимый контроль через системный Ruby каждые 5 минут. Сообщает в Telegram об аварийном завершении, исчезновении задания launchd или отсутствии завершённых проверок более 45 минут. Повторяет попытки доставки при сбое сети; после доставки предупреждает один раз за сбой и сообщает о восстановлении.
- `watchdog-config.json` — последняя сохранённая копия токена и ID чата для контроля при повреждении основной конфигурации; права `600`, не передавайте другим. Обновляется командой `install`.
- `watchdog-enabled.json`, `watchdog-state.json` — включение контроля и состояние предупреждений. Ручная остановка и настройка отключают предупреждения. После сна или перерыва в запуске контроля даётся 45 минут на возобновление проверок.
- `telegram-control.json` — срок паузы и позиция прочитанных команд; список подписчиков и личные сроки паузы. Команды принимаются только от самого пользователя в его личном чате; новый получатель добавляется только через `/start`. Существующий чат владельца и его пауза сохраняются при обновлении.
- `state.json` — последняя проверка и состояние уведомлений; токена в нём нет.
- `history.jsonl` — ограниченный по размеру журнал проверок без токена и cookies.
- `chrome-profile/` — отдельная сессия Google; содержит чувствительные данные входа, не передавайте её.
- `monitor.mjs`, `node_modules/` — установленная программа и Playwright Core 1.58.2. Используется установленный Google Chrome и Node.js 22.22.3.

Задания macOS: `~/Library/LaunchAgents/local.gym-monitor.plist` и `local.gym-monitor.watchdog.plist`. Независимый контроль не зависит от Node.js, но требует работающего Mac, пользовательской сессии, launchd, системного Ruby и доступа к Telegram; при отказе самого контроля, выключенном Mac или отсутствии интернета немедленное уведомление невозможно. Скрипт работает через launchd, открытый Terminal ему не нужен. Обновление или удаление установленной версии Node.js может потребовать переустановки задания с новым путём.

Исходник — `monitor.mjs` рядом с этой инструкцией; запускается его установленная копия из рабочей папки. Для обновления копии и задания выполните исходник с командой `install`. Команды Telegram проверяются примерно раз в минуту; запросы Google — раз в 10 минут. Ручная диагностическая проверка с `--dry-run` выполняется сразу, не меняет состояние, расписание запросов и не отправляет сообщения. Для сверки с видимым графиком: `check --dry-run --verify-live`. Интервалы задаются в исходнике; пороги и часы меняются в `config.json` (`confirmations: 3`, `cooldownMinutes: 60`). Краткое уведомление содержит отметку о низкой загрузке, текущий индекс Google из 100, время проверки по Нячангу и ссылку на карточку. Подробности подтверждения остаются в правилах выше. Это дискретные проверки относительного индекса, не непрерывное наблюдение и не фактическое количество людей. Даже совпадение API и графика не гарантирует точности самого Google. Дополнительный запрос общий для подписчиков; команды и паузы перепроверяются после него и перед каждой отправкой. Если результат старше минуты, отправка подавляется.

Парсинг Google неофициальный: изменение формата, выход из аккаунта или ограничение Google могут потребовать исправления скрипта. Подтверждены поиск правильной карточки, обработка отсутствующих данных, доставка Telegram, установка launchd и чтение реального live-показателя. Значение 59/100 — результат проверки при настройке, а не постоянно актуальное значение.
